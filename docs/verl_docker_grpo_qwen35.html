Policy optimization with verl and Docker

A deployment-oriented reference for running the FU-TCM BGPO/GRPO implementation from a supervised checkpoint on an NVIDIA GPU server.

Exact CUDA, PyTorch, vLLM, and verl compatibility changes over time. Confirm the current requirements in the official verl documentation before selecting an image.

Required local artifacts

ArtifactPurpose
Supervised FU-TCM checkpointModel configuration, tokenizer, and weights used as the policy initialization.
Local train and validation parquet filesPrivate BGPO/GRPO records. These files are intentionally excluded from Git.
reward_functions.pyProject-specific compute_score reward entry point.
Optional syndrome taxonomyEnables graded syndrome similarity through TCM_ZHENGHOU_BTREE; exact matching remains available without it.

Start the container

Select a verl image that matches the server driver and the required rollout backend.

export VERL_IMAGE="<compatible-verl-image>"
export FU_TCM_PROJECT="/path/to/FU-TCM/sft_grpo_training_evaluation"
export FU_TCM_MODEL="/path/to/sft-checkpoint"
export FU_TCM_PRIVATE_DATA="/path/to/private/parquet"
export FU_TCM_OUTPUT="/path/to/output"

docker run --rm -it \
  --gpus all \
  --net=host \
  --ipc=host \
  --shm-size=128g \
  -v "${FU_TCM_PROJECT}:/workspace/tcm:ro" \
  -v "${FU_TCM_MODEL}:/workspace/model:ro" \
  -v "${FU_TCM_PRIVATE_DATA}:/workspace/private:ro" \
  -v "${FU_TCM_OUTPUT}:/workspace/output" \
  -w /workspace/tcm \
  "${VERL_IMAGE}" bash
Keep source data and credentials outside the repository. Mount only the directories required for the training run.

Run the smoke test first

The repository script applies the compatibility shim and launches a small validation run. Override paths and resource settings through environment variables rather than editing the script.

cd /workspace/tcm

export TCM_MODEL_PATH=/workspace/model
export TCM_GRPO_TRAIN_FILE=/workspace/private/train.parquet
export TCM_GRPO_VAL_FILE=/workspace/private/validation.parquet
export TCM_GRPO_OUTPUT_DIR=/workspace/output/smoke

bash run_tcm_grpo_smoke.sh

The smoke run should confirm model loading, parquet loading, reward invocation, rollout startup, and an optimizer update before any full-scale run begins.

Reward configuration

custom_reward_function.path=/workspace/tcm/reward_functions.py
custom_reward_function.name=compute_score

Set the optional syndrome taxonomy only when the private file is available:

export TCM_ZHENGHOU_BTREE=/workspace/private/zhenghou_btree.json

Scaling checklist

  • Increase rollout count, response length, training batch size, and epochs only after the smoke test passes.
  • If vLLM initialization runs out of memory, reduce rollout memory utilization or response length, or increase tensor parallelism.
  • If the actor update runs out of memory, keep the per-GPU micro-batch small, retain optimizer offload, and reduce the PPO mini-batch.
  • Ensure that the selected tensor-parallel size divides the available GPU topology sensibly.
  • Pin the container image, verl commit, checkpoint, private-data version, environment overrides, and random seed for reproducible paper results.

Troubleshooting

Missing parquet files

ls -lh /workspace/private/*.parquet

PyTorch, vLLM, or Transformers incompatibility

Start from a compatible, pinned verl image. Avoid upgrading the core framework packages independently inside the container.

Qwen multimodal architecture mismatch

Check the model's config.json, its declared architecture, and the Transformers version bundled with the image. Apply a compatibility patch only when it is documented and pinned.
